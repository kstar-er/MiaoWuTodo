1. 产品目标
为桌面端宠物应用增加 AI 文档编辑能力，使用户可以在两种模式之间切换：
● 对话模式（Chat Mode）：用于自由对话、咨询、讨论文档内容
● 画布模式（Canvas Mode）：用于对当前文件进行 AI 协作编辑，并生成可确认的修改结果（diff）
目标能力：
● AI模型接口路径用户自己填写、自己选择模型、需要身份认证的能填写身份认证
● 不直接覆盖文件
● AI 修改需用户确认
● 支持版本回滚
● 支持单文件编辑

2. 核心概念定义
2.1 模式（Mode）
系统存在两种工作模式：
模式	用途	是否修改文件
Chat Mode	普通聊天 / 咨询	否
Canvas Mode	文档协作编辑	是（需确认）

2.2 画布（Canvas）
画布是一个文档编辑区域，用于：
● 展示当前文件内容
● 展示 AI 修改建议（diff）
● 支持用户确认或拒绝修改

2.3 版本（Version）
每次成功应用 AI 修改后，生成一个新的文档版本，至少保留最近 3 个版本。
版本包含：
● 原始内容
● 修改后内容
● 用户 Prompt
● AI 修改摘要
● 时间戳

3. 功能模块说明

3.1 模式切换功能（Chat / Canvas）
3.1.1 功能描述
用户可以在顶部或显著位置切换 AI 的工作模式：
● Chat 模式：AI 只回答问题
● Canvas 模式：AI 对选中文件执行编辑操作
3.1.2 UI 设计
顶部切换按钮：
[ Chat 模式 ]   [ Canvas 模式 ]
当前模式高亮显示。

3.1.3 交互逻辑
切换到 Chat 模式：
● 隐藏文件编辑相关 UI（diff、版本管理）
● 输入框变为普通聊天提示：
你可以向 AI 提问
切换到 Canvas 模式：
● 必须选择一个文件
● 若未选择文件，提示：
请先选择一个文件进入画布模式

3.1.4 技术逻辑
前端状态：
{
  "mode": "chat" | "canvas",
  "currentFile": "xxx.md"
}
模型调用路由：
if mode == chat → 调用对话模型
if mode == canvas → 调用文档编辑模型

3.2 单文件编辑功能（Canvas 模式）
3.2.1 功能描述
用户在 Canvas 模式中：
1. 选择一个文件
2. 输入编辑指令（Prompt）
3. AI 返回结构化修改建议（JSON diff）
4. 用户确认后应用修改到文件

3.2.2 用户流程
1. 用户切换到 Canvas 模式
2. 选择文件 A
3. 文件内容显示在画布区
4. 用户输入 Prompt：
请帮我优化这段文字，使更正式
5. 系统调用大模型
6. 展示 AI 修改 diff
7. 用户点击：
  ○ 「应用修改」或
  ○ 「拒绝修改」

3.2.3 模型调用逻辑
System Prompt（固定）
你是一个文档编辑助手。
用户会提供文件内容和编辑指令。
你必须返回 JSON 格式的修改指令。
禁止输出任何解释性文本。

返回格式：
{
  "summary": "...",
  "changes": [
    {
      "type": "replace",
      "start": number,
      "end": number,
      "new_text": "..."
    }
  ]
}
User Prompt
当前文件内容：
<<<FILE_CONTENT>>>

用户指令：
<<<USER_PROMPT>>>

3.2.4 返回结果处理
AI 返回 JSON 后：
前端解析：
● 根据 start / end 定位原文
● 渲染 diff（删除红色，新内容绿色）
● 显示 summary 作为本次修改说明

3.3 JSON Diff 返回机制
3.3.1 数据结构规范
{
  "summary": "优化了语句表达",
  "changes": [
    {
      "type": "replace",
      "start": 120,
      "end": 180,
      "new_text": "修改后的内容"
    }
  ]
}
字段说明：
字段	含义
summary	本次修改的摘要说明
changes	修改操作数组
type	操作类型（目前只支持 replace）
start	原文起始字符位置
end	原文结束字符位置
new_text	新文本内容

3.3.2 前端处理逻辑
● 不直接修改原文
● 生成临时修改预览
● 支持按钮：
  ○ 应用修改
  ○ 放弃修改

3.4 版本管理功能
3.4.1 功能描述
系统为每次成功应用的修改生成一个版本记录，至少保留最近 3 个版本。

3.4.2 版本数据结构
{
  "version_id": "v1.2",
  "timestamp": "2026-03-02 14:22",
  "prompt": "帮我改得更正式",
  "summary": "优化语气表达",
  "before_content": "...",
  "after_content": "..."
}

3.4.3 UI 展示
侧边栏显示版本列表：
版本历史：
v1 初始版本
v2 AI 优化语气
v3 用户调整段落
点击某版本：
● 展示该版本内容
● 可对比当前版本 diff
● 提供按钮：
  ○ 回滚到该版本

3.4.4 回滚逻辑
用户点击回滚：
● 当前文档内容替换为选中版本的 after_content
● 生成一个新的版本记录（回滚也是一次变更）

4. 异常与边界情况
4.1 未选择文件进入 Canvas 模式
提示：
请先选择一个文件

4.2 模型返回非 JSON
处理方式：
● 显示错误提示：
AI 返回格式错误，请重试
● 不修改文档

4.3 修改范围过大
当 changes 涉及全文超过 50%：
● 弹窗确认：
AI 修改内容较多，是否确认应用？

4.4 用户连续多次修改
每次修改都必须生成版本记录，最多保存最近 N 个版本（MVP 建议 N=3 或 5）


6. 技术架构简述
前端
● 状态管理：mode、currentFile、pendingDiff、versionList
● 编辑器组件：支持 diff 显示
● 按钮：应用修改 / 回滚 / 切换模式
后端
● 文档内容读取与保存
● 模型调用接口封装
● 版本存储（本地 JSON 或数据库）

7. 成功指标（MVP）
● 用户可以成功切换 Chat / Canvas 模式
● AI 能返回 JSON diff
● 用户可预览并确认修改
● 可回滚最近 3 次修改
● 单文件编辑完整闭环
